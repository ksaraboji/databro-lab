# Technical Doc -> Dev.to Publisher (Agentic Spike)

This spike ingests a technical documentation file and runs a fully agentic workflow to:

1. Extract key technical insights from the uploaded document.
2. Create curiosity-driven, emoji-rich long-form articles.
3. Convert Mermaid diagrams from the input doc into image URLs and embed them in the article.
4. Produce Dev.to-ready markdown with YAML front matter, tags, and cover metadata.
5. Optionally publish to Dev.to.
6. Save all generated artifacts and a run manifest.

## Agentic workflow

The workflow is intentionally task/agent-driven:

1. Technical Document Intake Analyst
2. Curiosity-Driven Story Architect
3. Dev.to Markdown Optimizer
4. Publishing Operations Agent

No manual content templating path is used for article writing. The article package is generated by agents and handled through tools.

## Features

- Upload technical documentation (`.md`, `.txt`)
- Curiosity-focused title strategy with emojis
- Dev.to markdown with YAML front matter
- Mermaid diagram extraction and image embedding via markdown image links
- Long-form article packaging with deeper technical coverage
- Tags and cover metadata generation
- Optional auto-publish mode
- Artifact persistence for auditability

## Setup

### 1. Create and activate venv

```bash
python3 -m venv venv
source venv/bin/activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure environment

```bash
cp .env.example .env
```

Set at least one LLM backend and model credentials.

If you want publishing enabled, configure:

- `DEVTO_API_KEY`

### 4. Run app

```bash
python app.py
```

Open `http://localhost:7860`.

## Usage

1. Upload technical documentation file.
2. Choose LLM backend/model.
3. Keep publish toggle off for draft mode, on for live publish.
4. Run workflow (Mermaid code blocks are automatically converted to image links and inserted into article markdown).
5. Download generated markdown artifacts from the UI.

## Output artifacts

Artifacts are stored under temp output directory and exposed in UI downloads:

- Dev.to markdown article
- Publication report markdown
- Publication manifest JSON

## Notes

- Dev.to tags are capped to 4 by API behavior.
- Publish errors are returned in manifest/report; artifact generation still succeeds.
